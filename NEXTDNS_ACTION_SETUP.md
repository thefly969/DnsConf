# Настройка автоматической синхронизации NextDNS

## Что делает workflow

- Получает hosts-файл GeoHide DNS из источника, указанного в статье Habr.
- Разбирает строки `IP domain` и формирует правила перенаправления NextDNS.
- Учитывает, что Rewrite NextDNS распространяется на указанный домен и его поддомены.
- Убирает дочернее правило, если ближайший родительский Rewrite уже выдаёт тот же IP.
- Сохраняет дочернее правило, если ему нужен другой IP.
- Сохраняет существующие правила профиля, домены которых отсутствуют в источнике.
- Проверяет будущий общий размер списка до первого изменения в API. При результате больше 500 останавливается без отправки изменений.
- Делает не более одного изменения API примерно за 1,1 секунды, чтобы не превышать лимит NextDNS.

## Учётные данные — только через секреты GitHub

Не добавляйте API-key в файлы репозитория, обычные переменные GitHub Actions, коммиты или журналы workflow. Не прикрепляйте файл с незашифрованным ключом к обсуждениям.

1. В репозитории откройте **Settings → Environments**.
2. Создайте окружение с именем `DNS`, если его ещё нет.
3. В окружении `DNS` откройте **Environment secrets** и добавьте:
   - `AUTH_SECRET` — API key NextDNS из `https://my.nextdns.io/account`.
   - `CLIENT_ID` — ID нужного профиля NextDNS из раздела Endpoints.

Оба значения читаются workflow как `secrets.AUTH_SECRET` и `secrets.CLIENT_ID`; в логи они не выводятся.

## Источник hosts

По умолчанию workflow использует:

`https://raw.githubusercontent.com/Internet-Helper/GeoHideDNS/refs/heads/main/hosts/hosts`

Чтобы заменить источник, создайте в окружении `DNS` переменную `REDIRECT`. Несколько ссылок указываются через запятую без пробелов. Если `REDIRECT` не задана, используется источник выше.

Дополнительные необязательные переменные окружения:

- `EXCLUDE_REDIRECT` — дополнительные пользовательские домены через запятую; сам домен и его поддомены не попадут в перенаправления, а существующие соответствующие Rewrite будут удалены.
- `src/main/resources/nextdns-redirect-source-exclusions.txt` — встроенный список исключений только для входящих hosts-источников; он не удаляет уже существующие пользовательские Rewrite.
- `DONOR_DNS` — необязательный DNS-донор для обновления IP, поддерживаемый самим DnsConf.
- `BLOCK` — необязательные источники доменов для списка блокировки. Для обычного сценария GeoHide оставьте пустым.

## Расписание и ручной запуск

Автоматический запуск установлен ежедневно в **03:00 по часовому поясу `Europe/Zurich`**. GitHub учитывает переходы CET/CEST автоматически.

Для ручной синхронизации откройте **Actions → DNS Block&Redirect Configurer cron task → Run workflow**. Это отдельная команда запуска; расписание продолжает работать независимо.

## Ограничение NextDNS

В одном профиле может быть не более 500 Rewrite, включая созданные вручную. Чтобы вместить максимально возможное число полезных перенаправлений, workflow заранее исключает выбранные группы доменов из входящих hosts-источников с помощью файла `src/main/resources/nextdns-redirect-source-exclusions.txt`. Эти исключения не удаляют существующие пользовательские Rewrite.

После фильтрации программа безопасно убирает дочернее правило, только если ближайший родительский Rewrite уже выдаёт тот же IP. Если итоговый объём всё равно превышает 500 из-за обновления источников или добавленных вручную правил, workflow завершится до отправки изменений в API — произвольного усечения оставшегося списка нет.

Правило для домена, присутствующего в актуальном hosts-источнике, считается управляемым источником: его IP можно обновить, а избыточную дочернюю запись — удалить. Правила для доменов, отсутствующих в источниках и не заданных в пользовательском `EXCLUDE_REDIRECT`, сохраняются как пользовательские.
