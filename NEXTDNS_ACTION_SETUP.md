# Настройка автоматической синхронизации NextDNS

## Что делает workflow

- Получает предпочтительные прокси-IP из `smart-no-crutch.hosts`, альтернативные IP из `combined-no-crutch.hosts` и прямые резервные адреса из `only-crutch.hosts` проекта RussiaFancyLists.
- Ограничивает дополнительные IP только доменами SMART allowlist; большой combined-файл не расширяет число доменов.
- Сохраняет разные IP одного домена как отдельные кандидаты, а не отбрасывает их при разборе hosts.
- Параллельно проверяет каждый IP/домен на TCP 443: TLS с именем сайта в SNI и проверкой HTTPS-сертификата. Испытывает альтернативы при неудаче предпочтительного IP.
- Если кандидат не проходит проверку, сохраняет текущее правило как последний известный адрес. Если доля проверенных доменов ниже безопасного порога, останавливается до изменения NextDNS.
- Для дочернего домена по возможности использует тот же проверенный IP, что и родитель, если он также проходит проверку для дочернего имени.
- Не заменяет проверенные адреса через DONOR_DNS.
- Учитывает, что Rewrite NextDNS распространяется на указанный домен и его поддомены.
- Убирает дочернее правило, если ближайший родительский Rewrite уже выдаёт тот же IP.
- Сохраняет дочернее правило, если ему нужен другой IP.
- Отслеживает ранее созданные скриптом правила в `state/managed-nextdns-rewrites.txt`; удаляет устаревшие правила старого источника и сохраняет пользовательские правила за пределами управляемого набора.
- Проверяет будущий общий размер списка до первого изменения в API. При результате больше 500 останавливается без отправки изменений.
- После успешной синхронизации обновляет список управляемых доменов отдельным коммитом GitHub Actions.
- Делает не более одного изменения API примерно за 1,1 секунды, чтобы не превышать лимит NextDNS.

## Учётные данные — только через секреты GitHub

Не добавляйте API-key в файлы репозитория, обычные переменные GitHub Actions, коммиты или журналы workflow. Не прикрепляйте файл с незашифрованным ключом к обсуждениям.

1. В репозитории откройте **Settings → Environments**.
2. Создайте окружение с именем `DNS`, если его ещё нет.
3. В окружении `DNS` откройте **Environment secrets** и добавьте:
   - `AUTH_SECRET` — API key NextDNS из `https://my.nextdns.io/account`.
   - `CLIENT_ID` — ID нужного профиля NextDNS из раздела Endpoints.

Оба значения читаются workflow как `secrets.AUTH_SECRET` и `secrets.CLIENT_ID`; в логи они не выводятся.

## Источник hosts

NextDNS workflow использует три закреплённых источника:

- Предпочтительные прокси: `https://raw.githubusercontent.com/Noktomezo/RussiaFancyLists/main/lists/hosts/smart-no-crutch.hosts`
- Альтернативы всех прокси-провайдеров: `https://raw.githubusercontent.com/Noktomezo/RussiaFancyLists/main/lists/hosts/combined-no-crutch.hosts`
- Прямые резервные адреса: `https://raw.githubusercontent.com/Noktomezo/RussiaFancyLists/main/lists/hosts/only-crutch.hosts`

Большой `combined-no-crutch.hosts` используется только как дополнительный пул IP для доменов SMART, не как источник новых доменов. Workflow проверяет каждый IP с именем сайта в SNI и проверкой HTTPS-сертификата. Затем выбирает рабочий адрес, предпочитая совпадение с проверенным адресом родительского домена для безопасного сокращения Rewrite.

Проверка выполняется на сервере GitHub Actions, а не в Вашей локальной сети. Она не проверяет ограничения конкретного оператора. Если оператор сбрасывает TLS по SNI после успешного DNS-разрешения, одни Rewrite такую блокировку не устранят: нужна отдельная защита от DPI или VPN.

URL закреплены в `.github/workflows/nextdns_sync.yml`. Переменная GitHub Environment `REDIRECT` в этом workflow не используется. Не задавайте `DONOR_DNS` для SMART: замена проверенного прокси-IP обычным DNS-ответом разрушит маршрут через прокси.

Дополнительная пользовательская переменная:
- `EXCLUDE_REDIRECT` — домены через запятую; сам домен и его поддомены не будут добавлены, а совпадающие существующие Rewrite будут удалены.
- `BLOCK` — необязательные источники доменов для списка блокировки.

## Расписание и ручной запуск

Автоматический запуск установлен ежедневно в **03:00 по часовому поясу `Europe/Zurich`**. GitHub учитывает переходы CET/CEST автоматически.

Для ручной синхронизации откройте **Actions → NextDNS SMART Rewrite Sync → Run workflow**. Это отдельная команда запуска; расписание продолжает работать независимо.

## Ограничение NextDNS

В одном профиле может быть не более 500 Rewrite, включая созданные вручную. Альтернативные IP не увеличивают доменный список: они привязаны только к доменам из SMART allowlist. При выборе маршрута программа предпочитает IP родителя для дочернего домена, только если этот же IP прошёл TLS/SNI-проверку для дочернего имени. Поэтому сокращение правил не меняет фактически выбранный адрес.

Перед первой записью workflow проверяет общий размер профиля. Если лимит превышен, он завершается до отправки изменений в API — случайного усечения списка нет. После успешной записи выполняется повторное чтение профиля, а список управляемых правил сохраняется в репозитории.

При переходе со старого источника удаляются только правила с доменами, перечисленными в первоначальном манифесте прежних hosts-источников. Остальные правила профиля, не принадлежащие этому управляемому набору и не попавшие под пользовательский `EXCLUDE_REDIRECT`, сохраняются.
